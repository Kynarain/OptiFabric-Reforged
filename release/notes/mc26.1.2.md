**Minecraft 26.1.2** / Fabric Loader 0.19.5 / **Java 25** / 需求 OptiFine `preview_OptiFine_26.1.2_HD_U_K1_pre2.jar`

> 你去哪拿、并**替你从 OptiFine 官网下载**(见下文"本版新增")。补丁管线一个字节没动,`2.0.0+mc26.1.2` 的用户

## 这个版本是什么

把 OptiFine 接入 Fabric,用于 **26.1.2** —— Minecraft 第一个**未混淆**的版本。

这一点让本版与 1.21.x 全系列有本质区别:官方名就是运行名,既没有 yarn 也没有真正的 intermediary
可重映射(26.1.2 只发布占位 `intermediary:0.0.0`)。因此 26.x 走的是独立的构建与运行期路径:
本 jar **只适配 Minecraft 26.1.2**,不要跨版本使用,也不要拿 1.21.x 的 jar 顶替。

## 本版修复:丢掉 Mixin 为被替换的类缓存的 ClassInfo(2.2.1)

Mixin 给每个类建一份元数据(`org.spongepowered.asm.mixin.transformer.ClassInfo`)并缓存,内容取自**它的字节码
提供者** —— 在 Fabric 上就是 Knot,也就是本模组的 game transformer。Fabric 在 `preLaunch` 入口点**之前**就已经把
Mixin 的配置准备好(本模组的 `OptifineSetup` 正是在 `preLaunch` 里跑的),所以对本模组替换掉的那些类,缓存里可能
已经存着**游戏自己的**那一份,而稍后交给 Mixin 变换的是 **OptiFine 的**那一份。两者对某个成员的记录一旦不一致,
需要解析局部变量的注入(Locals,`@ModifyVariable` 与 locals 捕获都走它)就会在 `ModifyVariableInjector.preInject`
里把**整个类**判失败并抛 `LVTGeneratorError`,而 Fabric 只报一句
`Mixin transformation of net.minecraft.class_757 failed` —— 这一步在 `require` / `expect` 之前,受影响的模组自己
没法绕开。

修复是 `GameTransformerHook` 记住**它实际替换掉**的类,安装完成后按**内部名**丢掉它们在 Mixin 缓存里的条目 —— 新文件
`mod/MixinClassMetadata.java`(113 行),每个类最多丢一次,取不到缓存时只报告一次、不影响其它逻辑(过期元数据仍然
能跑,只是那些解析类元数据的 mixin 照旧失败)。Mixin 于是按**它实际拿到**的字节重建元数据。字节仍是 Loader 自己那份的
类没有被替换,条目照旧保留。

**同一个修复在本仓库的 1.21.x 线上先落地并已真机实测**(主界面、进世界、光影包在世界里编译)。26.1.2 这一份的离线
数字与 2.2.0 记下的基线逐个相同(见文末「验证结果」)。

## 上一版新增:OptiFine 提示 + 官网下载(2.2.0)

26.2 那一份先拿到了这个功能;这一版把它按 26.1.2 的客户端 API 一起补上(代码同源,只有目标版本不同):

- **没装 OptiFine**:每次启动都在界面上告诉你缺哪个文件(这一次的关闭只在本会话有效);
- **装的是更旧的预览版**:每个构建只提示一次,记在 `config/optifabric-mismatch-ack.txt`;
- **已装正式版(final)**:完全不提示,哪怕有更新的正式版;
- 提示界面上的 `下载 OptiFine` 按钮**只从 OptiFine 官网取**(`optifine.net/adloadx`,本模组唯一会用的来源),
  下载**保存前先校验**(同时接受 `srg/net/optifine/Config.class` 这种新布局),旁边就是打开 mods 文件夹;
  地址栏可以换成你自己的地址,那就只从你填的地方取 —— 本包**不含、也不分发** OptiFine,也不指向任何第三方镜像;
- **Windows 上下载完会自动重启游戏**:走 JNA 的 `GetCommandLineW` + `CreateProcessW`(26.x 自带 JNA 5.17.0),
  所以 `build.gradle` 多了两条 `compileOnly` 的 JNA 依赖(只编译期使用,不进 jar)。

## 26.x 为什么需要单独一版

- **mod id 与显示名**:这一线是 `optifabric_reforged` / **OptiFabric Reforged**(1.21.x 仍是 `optifabric`)。有些模组
  声明 `"breaks": {"optifabric": "*"}`(例如 LambdaBetterGrass),而 Fabric Loader 按 **id** 匹配,所以只有换 id 才能
  不被它们拦住;实测上游**未修改**的 LBG jar 现在可以与本模组一起启动;
- **构建**:Loom 的**非重映射** flavour(`net.fabricmc.fabric-loom`),不写 `mappings`;jar 里也不再打包
  `official→intermediary` 映射表(未混淆下没有东西可映射);
- **运行期**:命名空间是 `official` 而不是 `intermediary`,整个"官方名 → intermediary"重映射被跳过;
- **fixer**:1.21.x 那套按 `class_XXXX` 注册的判据在未混淆版本里指向的类**根本不存在**,所以本版另建了一张
  "官方名"注册表,按官方名与官方判据工作。

## 本版修复

- **注入点(最主要的一类)**:OptiFine 重编译时会把原版方法**削成薄壳**、把真正的实现搬进它自己加的一个重载,
  而 Fabric API 用**不带描述符**的 `method = "..."` 指名目标 —— 恢复原版方法体之后类里出现两个同名方法,
  MixinExtras 建不出局部变量上下文,整个类变换失败。逐处消歧:
  `LevelRenderer`(移动方块/方块描边)、`SectionCompiler`(区块重建)、`CuboidItemModelWrapper`(物品模型)、
  `ScreenEffectRenderer`(水下/着火遮罩)、`ModelManager`(模型加载);
- **渲染器(FRAPI)**:26.1 把 Fabric 渲染器 API 挪进了 `api.client.renderer.v1`,按旧名字查找失败使占位
  **从未注册**,第一个 `Renderer.get()` 就把游戏带走;而且占位**不再抛异常** —— Fabric API 自己的渲染钩子会在
  普通帧里调用它。更根本的是,从 1.21.x 继承来的 `fabric-renderer-api-v1:contains_renderer` 让位键在这一线
  **本来就是多余的**:26.1.2 的 indigo 已经不是地形渲染器(地形与提交节点的整合搬进了 `fabric-renderer-api-v1`
  自己,它只剩 1 条物品 mixin + 2 个 accessor),键一声明就把 Fabric API 唯一能问到的渲染器关掉,模组网格进
  惰性占位 —— 不报错,也不显示。本版**不再声明该键**,由 Indigo 注册自己的 `IndigoRenderer`;
- **实时几何(FRAPI)**:Fabric 的地形渲染钩子注入在原版 `compile` 的循环上,而 OptiFine 的区块构建方法里没有那个
  循环 —— 钩子永不执行,需要按方块位置实时生成几何的模型(LambdaBetterGrass 这类)`emitQuads` 一次都没被问过,
  几何静默消失。现在新增一条桥:几何由 Fabric 的渲染器产出,**顶点交给 OptiFine 自己的 `BlockQuadOutput` 写**,
  所以顶点格式、层级、光照与光影属性全归 OptiFine。实测:**LBG 的"更好的草"正常、连接纹理正确(光影开启)**。
  只路由模型自身声明的几何,原版方块仍走 OptiFine 的路径;
- **抗锯齿**:26.x 从 `post_effect/` 读后处理链,而 1.21.x 那套修复的做法是**删掉该文件**、补写老位置的链 ——
  在这一线正好是反的。现在按版本线分开处理,26.x 原样保留 OptiFine 自带的 `post_effect/`;
- **渲染路径**:移动方块与普通方块模型这两处 Fabric API 钩子仍为惰性(由原版/OptiFine 路径绘制);方块破坏
  裂纹那条没有动,它现在真的走 Indigo 的渲染器。

## 安装

1. 安装 Fabric Loader 0.19.5(**Java 25 或更高**,26.1.2 本身要求 Java 25);
2. 把本 jar 与 26.1.2 的 OptiFine 一起放进该版本的 `mods\` 目录;
3. 启动一次即可(首次会做补丁 + 建立 `.optifine` 缓存,多花几秒)。

OptiFine 需自行获取(本包不含、也不分发 OptiFine)。**本版会替你从官网取**:启动时若缺 OptiFine(或装的是更旧的
预览版),界面上会出现 `下载 OptiFine` 按钮,它从 OptiFine 官网(`optifine.net/adloadx`)下载并校验
`preview_OptiFine_26.1.2_HD_U_K1_pre2.jar`。想手动下载,去 <https://optifine.net/downloads> 的
**Preview versions** 那一节即可(本模组不再给出任何第三方镜像地址)。

## 已知限制

- **只支持 26.1.2**;26.1 的其他小版本与 26.2+ 需要各自重新移植,不能直接用;
- 26.1.2 的 OptiFine 目前只有 **preview** 构建(`HD_U_K1_pre2`);
- 依赖 Fabric 渲染器 API(FRAPI)的模组在这一线能拿到**真正的渲染器**,而且**自己实时生成的几何会被画出来**
  (实测 LambdaBetterGrass 正常,含连接纹理);只有"移动方块提交 / 方块模型提交"这两条 Fabric 钩子仍被有意停用;
- 1.21.x 全系列不受影响,仍由那条线自己的 jar 提供(1.21 与 1.21.1 是 `1.1.0`,1.21.3 – 1.21.11 是 `1.1.2`;
  那一线 indigo 依旧让位,依赖 FRAPI 的模组没有 indigo 渲染)。

## 验证结果(2.2.1)

离线(`powershell -NoProfile -ExecutionPolicy Bypass -File test-downloads\verify-26.ps1 -Version 26.1.2`,用的是这一版
自己的 `OptiFabric-Reforged-2.2.1+mc26.1.2.jar`):`Prepared 567 patched classes (0 skipped, 0 failed)`、
`verified OK: 567`、`FAILED: 0`、`ASM verifier problems: 0`;OptiFine 自身的类 **879 / 879**(2 个 Forge-only 类不适用)、
ASM 0;`AtTargetScan PROBLEMS: 0`(35 个调用点,1 个不支持的 kind)、`RefmapScan MISSING members: 0`、
`RuntimeContractScan` broken 0 / lost overrides 0 / unresolvable 0、`LambdaScan DANGLING handles: 0`。
数字与 2.0.0 / 2.2.0 记下的基线**逐个相同** —— 2.2.1 的改动发生在补丁**安装之后**(丢 Mixin 缓存条目),不参与字节码
修复,所以补丁类数量与验证器结论都不该动。

**真机端到端**(主界面、进世界、光影包在世界里编译)是在 **1.21.x 线**上用同一个修复做的;26.1.2 这一份**没有**在
真机上重跑 —— 本页 2.0.0 那一版的真机记录(启动、进世界、渲染、抗锯齿、光影、多人)仍然成立,但那是上一份产物。
2.2.1 真正要跑起来的那一步(`GameTransformerHook` 装类时丢缓存)只在**启动期**执行,离线校验覆盖不到。
