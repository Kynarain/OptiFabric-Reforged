# OptiFabric Reforged 2.1.1+mc26.2

**Minecraft 26.2** / Fabric Loader 0.19.5 / **Java 25** / 需求 OptiFine `preview_OptiFine_26.2_HD_U_K2_pre1.jar`

状态:**已实测**(世界打开并正常渲染;无崩溃、无 mixin 变换失败)。

> ### ⚠️ 光影在 26.2 上不可用(这一段先看)
>
> 26.2 这一版 OptiFine(preview `HD_U_K2_pre1`)在 `Shaders.loadShaderPack` 里**自己取消了光影包加载** ——
> 任何光影包都加载不了,连 OptiFine 自带的那份也不行(日志:`[Shaders] No shaderpack loaded.`)。
>
> 本模组**不修这一处**,而是把它**原样留成 OptiFine 写的样子**:OptiFine 的视频设置里仍然可以选光影包,但选了
> **不会有任何效果,也不会报错提醒你**。世界本身打开、渲染正常。想用光影请留在 **26.1.2**(`2.0.0+mc26.1.2`),
> 那一版的光影是正常的。
>
> 为什么不去"修"它:2.1.0 试过,结果更糟(见下)。

> ### ⚠️ 装了 2.1.0 的人请换成这一版
>
> - **本模组的 jar 要换**:26.2 用 `OptiFabric-Reforged-2.1.1+mc26.2.jar`。26.1.2 那份
>   `OptiFabric-Reforged-2.0.0+mc26.1.2.jar` **内容没有变**,别把它放进 26.2 的实例里;
> - **2.1.0 有一个必须撤掉的改动**:它把 OptiFine 那句取消删掉、把光影包加载**强行打开**。结果不是光影变好,而是
>   **选了光影包之后世界看不见** —— 画面只剩粒子,方块全是透视的(27 个 shader program 编译完成,任何日志里都没有
>   报错);同一个实例把 `shaderPack=OFF` 就画得正常;
> - **OptiFine 也要换**:26.2 必须配 `preview_OptiFine_26.2_HD_U_K2_pre1.jar`。本模组会读 OptiFine 的 `MC_VERSION`
>   校验版本,而且**两个版本的 OptiFine 同时在场会被判成 `DUPLICATED`** —— 换的时候先把 26.1.2 那份删掉;
> - 换完 jar 若发现行为与 2.1.0 一样,先删掉 `<游戏目录>/.optifine/` 再启动:缓存里存的是**打过补丁的字节码**,
>   删掉即强制重建。

## 这个版本是什么

把 OptiFine 接入 Fabric,用于 **26.2**(2026-09-15 发布)。26.2 与 26.1.2 一样**未混淆** —— 官方名就是运行名,
既没有 yarn,也没有真正可用的 intermediary 可重映射。所以这一版的构建侧一个字都没改:还是 Loom 的非重映射
flavour,目标版本只来自根目录 `gradle.properties` 的 `minecraft_version=26.2`。

**2.1.1 改了什么**:只有一处 —— `mod/OptifineJarFixer.java` 的 `enableShaderPackLoad` **只保留 1.21.6 / 1.21.7
那种形状原有的判据**(`ICONST_1, ISTORE, ILOAD, IFNE` 四步**紧邻**),**为 26.2 那种形状写的扩展判据整段删除**。
26.2 那种形状(赋值与判断**之间**夹了一次 `shaderPack` 配置读取)因此**不再被改动**;这次测量的结论同时写在类注释
与那段行内注释里。1.21.6 / 1.21.7 的修复不变(那是另一种形状,照旧把加载补回来)。

**版本号为什么是 2.1.1**:按 [语义化版本](https://semver.org/lang/zh-CN/)与
[`docs/VERSIONING.md`](../docs/VERSIONING.md),「修 fixer、修兼容性 → 修订号」。这一版**不移除任何支持、也不新增
支持范围**,只是撤回 2.1.0 里那次改坏了的修复。已发布的 `2.1.0+mc26.2` 按 §3 冻结(它那份 jar 与它那一节记录都
原样留着);26.1.2 继续用 `2.0.0+mc26.1.2`,那份 jar 的内容不变。

本 jar **只适配 Minecraft 26.2**,不要跨版本使用,也不要拿 1.21.x 的 jar 顶替。

## 26.2 上移动或改名的四处

1. **`Minecraft.setScreen` 没了**:26.2 换成了 `setScreenAndShow`。本模组报告错误时的那次调用因此编译失败
   (`找不到符号: 方法 setScreen(ConfirmScreen)`);26.1.2 上两个名字都在,所以改用 `setScreenAndShow` 之后两边都能编译;
2. **方块描边那一趟搬了家**:26.2 把 `extractBlockOutline` 从 `LevelRenderer` 挪进新类
   `net/minecraft/client/renderer/extract/LevelExtractor`,Fabric API 也跟着搬(它的处理器现在是
   `LevelExtractorMixin.hasMaterialFlagProxy`),于是原来按 `LevelRenderer` 注册的修复不再命中。现在为
   `LevelExtractor` 补了同一对修复(补回被 OptiFine 掏成空壳的原版方法体 + 丢掉原版已不存在的那几个重载),
   **旧判据同时保留** —— 26.1.2 上没有 `LevelExtractor`,那条在新版本上是空操作;
3. **区块重建任务类改名**:`SectionRenderDispatcher$RenderSection$RebuildTask` → **`…$CompileTask`**。OptiFine 把
   `SectionCompiler.compile(...)` 改名后需要把调用者一起改过去,而那条修复按类名注册 —— 不跟着改名,第一次区块重建
   (也就是**开存档后的第一帧**)会抛 `NoSuchMethodError`。现在这条重定向也注册在 `CompileTask` 上(同样与旧的那条并存);
4. **光影包一个都加载不了(OptiFine 26.2 preview 自身的缺陷)—— 这一处故意不修**:这一版的 `Shaders.loadShaderPack`
   把"取消"标志位置真之后就跳过了真正的加载,连 OptiFine 自带的那份光影也不行。**2.1.0 试过强行打开它**:判据确实
   命中了(日志打出 `[Shaders] Loaded shaderpack: ComplementaryReimagined_r5.9.1.zip`),但选了光影包之后世界
   **只画粒子、方块透明**(27 个 program 编译完成,任何日志里都没有报错),同一个实例把 `shaderPack=OFF` 就正常。
   也就是说这一版 OptiFine 的光影管线还没做完,而那句"取消加载"正是让它不插手画面的开关 —— **2.1.1 因此把那条判据
   整段删除,那段字节码原样留给 OptiFine**,26.2 上"光影不可用"作为限制写明(见文首与"已知限制")。

## 安装

1. 安装 Fabric Loader 0.19.5(**Java 25 或更高**,26.2 本身要求 Java 25);
2. 把本 jar 与 **26.2 的 OptiFine** 一起放进该版本的 `mods\` 目录(不要同时放 26.1.2 的那份);
3. 启动一次即可(首次会做补丁 + 建立 `.optifine` 缓存,多花几秒)。

OptiFine 需自行获取(本包不含、也不分发 OptiFine)。国内镜像实测可用:

```
curl.exe -L -o preview_OptiFine_26.2_HD_U_K2_pre1.jar "https://bmclapi2.bangbang93.com/optifine/26.2/HD_U_K2/pre1"
```

下载下来可核对:**7783636 字节**,
`SHA-256: DB05B25F8AA5AC688A77354680EF939D4F3135350E64E7CCFE5996CFAF925927`。

Fabric API 可以一起加载(本版实测 `0.161.0+26.2`)。

## 已知限制

- **26.2 上光影不可用**:这个 OptiFine 构建里那句取消加载原样留着,在 OptiFine 里选光影包**不会有任何效果、也不会
  报错**;强行打开则会得到"只画粒子、方块透明"的画面(2.1.0 就是这个结果)。光影在 26.1.2 上照旧可用;
- 26.2 的 OptiFine 目前只有 **preview** 构建(`HD_U_K2_pre1`),与 26.1.2 当时一样;
- 多人与抗锯齿没有在 26.2 上重跑,那两项仍是 26.1.2 / 2.0.0 的记录;
- **26.2.1 与 26.3 支持不了**:这两版 Minecraft 确实存在,但 OptiFine 至今没有为它们发布任何构建,没有可移植的对象;
- 26.1.2 不受影响,仍由已发布的 `2.0.0+mc26.1.2` 提供(那份 jar 的内容不变);
- 依赖 Fabric 渲染器 API(FRAPI)的模组在这一线能拿到**真正的渲染器**,**只有"移动方块提交 / 方块模型提交"这两条
  Fabric 钩子仍被有意停用**(方块破坏裂纹那条没有动,它确实走 Fabric 的渲染器)—— 这条行为自 2.0.0 起没变,
  当时是在 26.1.2 上用 LambdaBetterGrass 实测的;
- 1.21.x 全系列不受影响,仍由那条线自己的 jar 提供(1.21 与 1.21.1 是 `1.1.0`,1.21.3 – 1.21.11 是 `1.1.2`)。
