# The 1.21.1 compatibility sweep — what these files are

This directory is a **snapshot** of the user-facing reports produced by an empirical compatibility sweep of
**OptiFabric Reforged 2.2.1 + OptiFine `HD_U_J1`** against popular Fabric mods for **Minecraft 1.21.1**
(Fabric Loader 0.19.5, offline account, one mod per run). The summary for readers is
[`../COMPATIBILITY.md`](../COMPATIBILITY.md) (Chinese: [`../COMPATIBILITY_CN.md`](../COMPATIBILITY_CN.md)).

Snapshot date: **2026-10-03**.
Source: the sweep workspace `compat-matrix\` (not part of this repository).

The copies were re-verified against the sweep workspace on 2026-10-03. **They are the sweep's current build of each
report, and `MATRIX.md` already includes the CurseForge batch** — it is the build whose own header reads
`Generated 2026-10-03T04:40:46.188Z` (= 12:40:46 +08:00), made from the merged `results.json` that holds all 49
launched CurseForge rows. Each file's LF-canonical SHA-256 was recomputed from both sides and matches, so no content
change was needed, so inside this directory the only things this pass touched are `upstream-optifabric-probe.md` (new here) and this
index.

## Provenance of the copies

The four files are **verbatim copies** of the sweep's own reports, adjusted only for this repository's line-ending
rule (`.md`: UTF-8, no BOM — see [`../../CONTRIBUTING.md`](../../CONTRIBUTING.md) §五):

| File | Transformation applied | Verification |
|---|---|---|
| `MATRIX.md` | LF → CRLF (the sweep file is LF) | 106,748 → 107,525 bytes; LF-normalised copy hashes to `B1F8B105…`, the source's own hash |
| `README.md` | LF → CRLF (the sweep file is LF) | 42,330 → 42,909 bytes; LF-normalised copy hashes to `E6AE320E…`, the source's own hash |
| `LIST.md` | **none** — the sweep's own `LIST.md` is already CRLF | the copy is byte-identical to the source (raw SHA-256 `78D995D1…` on both). Only for this file did the previous pass record the **raw on-disk** hash in the "LF form" column; its LF-canonical hash is `98516A35…`, and LF-normalising the copy still reproduces the source exactly |
| `upstream-optifabric-probe.md` | LF → CRLF (the sweep file is LF) | 3,937 → 4,011 bytes; LF-normalised copy hashes to `C645F167…`, the source's own hash |

The "Source bytes" column is the size of the sweep's file, so for `LIST.md` it equals the size in this directory and
for the other three it is 1 byte per line smaller than the copy here. Any hash above can be re-checked by stripping
CR from the copy; the byte counts are of the source files.

Paths mentioned *inside* these files — `logs\<mod>\`, `tools\`, `lanes\`, `cache\`, `deps\`, `results.json` — describe
the sweep workspace and **do not exist in this repository**. They are left in place so the reports stay faithful to
their source; every verdict's quoted log line can be traced back there.

## What was deliberately not copied

| Not copied | Why |
|---|---|
| `cache\`, `lanes\`, `deps\`, `sample\`, `curseforge\cache\`, `mirror-candidate-*\` | bulk run artifacts: downloaded jars, per-lane game directories, API reply caches. Hundreds of megabytes, and none of it is a report |
| `logs\<mod>\` and `lanes\lane*\logs\` | the raw evidence (a `latest.log`, crash reports, `verdict.json`, the staged mods manifest per row). It stays in the workspace; the reports quote the decisive line from each |
| every `*.json` (`results.json` 302 KB, `analysis.json` 114 KB, `plan.json` 300 KB, `pool*.json`, `class-names.json`, …) | machine-readable intermediates; too large to belong in a documentation directory, and summarised by `MATRIX.md` |
| `tools\` (the Node/PowerShell rig) | the rig itself. Reproducing a run needs the workspace, not a copy of the scripts here |
| `PAUSED.md` | workspace-state, not a report: it records what is complete, the exact re-run queues and the single command (`lanes\resume.ps1`) that resumes the sweep. Its content is summarised in [`../COMPATIBILITY.md`](../COMPATIBILITY.md) §6 |
| `declared-incompat.json` | it is the intermediate the probe file corrects: its `note` wrongly claims `conflicts` is a hard refusal by the loader, and its `upstream` block was probed against `master`, which declares neither `conflicts` nor `breaks`. The probe file is kept instead; see its §3 and §5 |
| `BASELINE-CANDIDATES.md`, `curseforge\README.md` | notes about the rig's baseline and the CurseForge collection path; they describe the workspace, not the result |

## The run is paused

At the snapshot the sweep was **paused at a clean row boundary**, with nothing running. Two re-run queues were still
owed: 4 rows whose own run or control produced nothing usable (`carpet-fixes`, `rei`, `bobby`, `freecam`) and 4
CurseForge rows (two invalid `DEP` rows measured before a missing dependency was restored, and two timeouts). The 50
extended rows past rank 200 were dropped by design, and the 100-row random-sample study was drawn and queued but
**never launched**. A resumed run would change the numbers in these files; nothing here should be treated as final.

## Known inconsistencies in the copied reports

The copies are verbatim, so the defects of the source reports travel with them. These are worth knowing before
quoting a number:

1. **`MATRIX.md` still disagrees with itself about a fourth "unexplained" failure**, exactly as before. Its summary
   line *"Failures split by what the no-OptiFine control showed: 27 incompatible with OptiFine, 4 unexplained, 4
   broken on plain Fabric 1.21.1"* and its *Failures grouped by what actually broke* table both total **35**, while
   its own per-row `Implicated layer` values give **27 + 4 + 3 = 34** for the 34 FAILs — `27`
   `mod-incompatible-with-optifine`, `4` `mod-broken-on-plain-fabric` and `3` `unexplained`. The fourth
   "unexplained" row is `carpet-fixes`, which is a `HARNESS-ERROR`, not a FAIL. The row-level split is the one to
   use; it is also the split in the sweep's own `PAUSED.md` and in [`../COMPATIBILITY.md`](../COMPATIBILITY.md) §3–§4.
2. **`LIST.md` is an earlier build than `MATRIX.md`** and its headline counts are stale — see the table above.
3. **`MATRIX.md` lists N/A as 19, the merged record as 18.** The extra row is `fabric-api`, which is part of every
   run's base set and therefore cannot be a subject (the report lists it with verdict `N/A` and the reason recorded).
4. **`MATRIX.md` leaves the *Target class in OptiFine's rewritten set?* column blank (`—`) for all 49 CurseForge
   rows**, including its 4 CurseForge FAILs. Its class attribution therefore covers the Modrinth rows only; the four
   CurseForge failures are still owned through their control runs (`mod-broken-on-plain-fabric`), so the blanks do
   not change the attribution — but a reader counting "FAILs that name a rewritten class" from this report alone
   gets the Modrinth-side number.
5. **`MATRIX.md`'s summary line "Work queue for the parallel phase: 111 rows (… 0 CurseForge)" describes the
   phase-1 queue, not the batch.** The CurseForge batch is a separate section of the same report
   (*## The CurseForge batch*: 49 launched, `structory` not run) and is included in the 34 FAILs and in the phase
   coverage table.
