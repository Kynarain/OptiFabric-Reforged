# The 1.21.1 compatibility sweep — what these files are

This directory is a **snapshot** of the user-facing reports produced by an empirical compatibility sweep of
**OptiFabric Reforged 2.2.1 + OptiFine `HD_U_J1`** against popular Fabric mods for **Minecraft 1.21.1**
(Fabric Loader 0.19.5, offline account, one mod per run). The summary for readers is
[`../COMPATIBILITY.md`](../COMPATIBILITY.md) (Chinese: [`../COMPATIBILITY_CN.md`](../COMPATIBILITY_CN.md)).

Snapshot date: **2026-10-03**.
Source: the sweep workspace `compat-matrix\` (not part of this repository).

## Provenance of the copies

The three files are **verbatim copies** of the sweep's own reports; the only change is that line endings were
normalised from LF to CRLF, as this repository requires for `.md` (UTF-8, no BOM — see
[`../../CONTRIBUTING.md`](../../CONTRIBUTING.md) §五). Stripping the CRLF normalisation reproduces the source
file's SHA-256 exactly, and the byte counts above are of the source files.

Paths mentioned *inside* these files — `logs\<mod>\`, `tools\`, `lanes\`, `cache\`, `deps\`, `results.json` — describe
the sweep workspace and **do not exist in this repository**. They are left in place so the reports stay faithful to
their source; every verdict's quoted log line can be traced back there.

## What was deliberately not copied

| Not copied | Why |
|---|---|
| `cache\`, `lanes\`, `deps\`, `sample\`, `curseforge\cache\`, `mirror-candidate-*\` | bulk run artifacts: downloaded jars, per-lane game directories, API reply caches. Hundreds of megabytes, and none of it is a report |
| `logs\<mod>\` and `lanes\lane*\logs\` | the raw evidence (a `latest.log`, crash reports, `verdict.json`, the staged mods manifest per row). It stays in the workspace; the reports quote the decisive line from each |
| every `*.json` (`results.json` 295 KB, `plan.json` 293 KB, `pool*.json`, `analysis.json`, `class-names.json`, …) | machine-readable intermediates; too large to belong in a documentation directory, and summarised by `MATRIX.md` |
| `tools\` (76 Node/PowerShell scripts) | the rig itself. Reproducing a run needs the workspace, not a copy of the scripts here |
| `PAUSED.md` | workspace-state, not a report: it records what is complete, the exact re-run queues and the single command (`lanes\resume.ps1`) that resumes the sweep. Its content is summarised in [`../COMPATIBILITY.md`](../COMPATIBILITY.md) §5 |
| `BASELINE-CANDIDATES.md`, `curseforge\README.md` | notes about the rig's baseline and the CurseForge collection path; they describe the workspace, not the result |

## The run is paused

At the snapshot the sweep was **paused at a clean row boundary**, with nothing running. Two re-run queues were still
owed: 4 rows whose own run or control produced nothing usable (`carpet-fixes`, `rei`, `bobby`, `freecam`) and 4
CurseForge rows (two invalid `DEP` rows measured before a missing dependency was restored, and two timeouts). The 50
extended rows past rank 200 were dropped by design, and the 100-row random-sample study was drawn and queued but
**never launched**. A resumed run would change the numbers in these files; nothing here should be treated as final.

## Known inconsistencies in the copied reports

The copies are verbatim, so the defects of the source reports travel with them. Three are worth knowing before
quoting a number:

1. **`MATRIX.md` disagrees with itself about the fourth "unexplained" failure.** Its summary and its *Failures grouped
   by what actually broke* table both say 4 failures are unexplained, but its own per-row `Implicated layer` values
   give **3** unexplained rows among the 34 FAILs — the fourth is `carpet-fixes`, which is a `HARNESS-ERROR` row, not
   a FAIL. The row-level data is the one to use: 27 `mod-incompatible-with-optifine`, 4
   `mod-broken-on-plain-fabric`, 3 `unexplained-control-failed-to-run` = 34. The same split is in the sweep's own
   `PAUSED.md` and in [`../COMPATIBILITY.md`](../COMPATIBILITY.md).
2. **`LIST.md` is an earlier build than `MATRIX.md`** and its headline counts are stale — see the table above.
3. **`MATRIX.md` lists N/A as 19, the merged record as 18.** The extra row is `fabric-api`, which is part of every
   run's base set and therefore cannot be a subject (the report lists it with verdict `N/A` and the reason recorded).
